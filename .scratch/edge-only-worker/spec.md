## Problem Statement

配對執行單元目前同時承載三種進場語意：`edge` 跨 broker 淨利差套利，以及 `donchian` 突破、`momentum` 正規化動量兩種 leader-only 趨勢跟隨。趨勢模式附帶一整套單腿運作流程：非對稱保護（獲利腿只留停損加移動停損、避險腿只留靜態停損）、單飛續跑（`peer_leg_empty` 時獲利腿繼續持有）、單飛鎖定（solo lock）、趨勢時間尺度的報價寬限與去 skew 閘門、逐門計數與 mid tape。維護者每次改進場、保護或收斂邏輯都要同時推理兩種互斥的心智模型，測試矩陣三倍膨脹，營運者也難以回答「這對到底是套利還是趨勢單」。

## Solution

將配對執行單元收斂為單一心智模型：只有 `edge` 跨 broker 淨利差套利一種進場語意與鏡像盒式保護，不存在模式切換。`entry_mode` 設定鍵與政策欄位本身完全刪除（不保留 `entry_mode=edge` 常數、不保留字串相容層）；`donchian`、`momentum` 兩種 solo 模式及其單腿運作流程從產品碼中刪除。同時移除「一腿最大化獲利、另一腿只守虧損」的非對稱目標概念：兩腿永遠是對稱的鏡像保護，沒有獲利腿／避險腿之分，沒有 winner-only 分流。此後最佳進場候選只有一種定義，保護只有一種形狀，對側清空只有一種處置（跟隨關閉，不單飛）。趨勢偏置函數、趨勢政策鍵、單飛事件、單飛鎖定、獲利腿移動停損從產品碼中刪除，不保留相容開關或影子分支。

## User Stories

1. As a 策略擁有者, I want 配對只有 edge 一種進場定義且沒有模式切換鍵, so that 每次檢討都是同一種損益結構。
2. As a 配對 leader 帳戶工作者, I want 只評估跨 broker 淨利差門檻並以淨利差 USD 排序, so that 候選選擇可解釋且可重播。
3. As a 配對 follower 帳戶工作者, I want 繼續只做非市場安全檢查而不重估報價或 edge, so that 執行語意不因刪除趨勢模式而改變。
4. As a 營運者, I want 設定檔與 canonical 政策裡根本沒有 entry_mode 鍵, so that 誤填任何模式值時啟動即失敗而不是靜默忽略。
5. As a 營運者, I want 已持久化的舊趨勢政策在重啟後 fail-closed 而非被 reinterpret 為 edge, so that 不會把趨勢單誤當套利單執行。
6. As a 風控擁有者, I want 每帳戶紐約已實現虧損預算與單腿允許損失計算維持不變, so that 刪除趨勢模式不放寬任何損失上限。
7. As a 配對執行單元, I want 任一腿清空時另一腿立即跟隨市價關閉, so that 整對損益鎖定於進場淨利差附近且永不出現雙份虧損的單飛結構。
8. As a 風控擁有者, I want 兩腿永遠對稱、沒有獲利腿與避險腿之分, so that 不存在一腿最大化獲利而另一腿只守虧損的非對稱目標。
8. As a 帳戶工作者, I want 限時同步配對退出與休市平倉維持兩側各自收斂至 desired-EMPTY, so that 刪除單飛後仍有確定的最長持有邊界。
9. As a 帳戶工作者, I want 重連後冷靜、失聯安全平倉、平倉收據對賬維持不變, so that 可用性機制不受策略簡化影響。
10. As a 稽核者, I want cell transitions 不再出現單飛事件而只剩跟隨關閉事件, so that 日誌詞彙與配對商品隔離、對帳邏輯一致。
11. As a 影子模式使用者, I want 影子路徑只演練 edge 候選排名與立即派遣進場決策, so that 比較新舊路徑時沒有趨勢分支干擾。
12. As a 測試維護者, I want 趨勢與單飛的測試案例被刪除且 edge 鏡像行為的覆蓋率不下降, so that 未來重構只針對一個行為面。
13. As a 未來開發者, I want 讀不到趨勢偏置、趨勢報價年齡、單飛鎖定的殘留概念, so that 不會誤以為單腿續跑仍是支援的產品行為。

## Implementation Decisions

- 進場模式鍵刪除：`entry_mode` 設定鍵、canonical 政策欄位、政策雜湊覆蓋範圍、持久化欄位從產品碼中完全移除，不是收斂為常數 `edge`。任何設定檔或已持久化政策若仍含該鍵或 `donchian`／`momentum` 值，視為政策損毀而 fail-closed。
- Shared 政策瘦身：趨勢家族的可調參數（lookback／突破緩衝／最小區間／動量時間窗與倍數／動量下限／spread 上限／coverage／趨勢報價年齡寬限）從 leader 撰寫的 shared 政策中移除，策略政策雜湊的涵蓋範圍同步縮小。報價新鮮度只剩 edge 的跨 broker 年齡與 skew 上限。
- 最佳進場候選定義凍結為 edge 版本：淨利差下限門檻加淨利差 USD 排序，逐門計數只保留缺報價／過期／skew／無量規劃等 edge 閘門；趨勢定向、趨勢強度排序鍵、趨勢暖機閘門刪除。
- 保護形狀唯一化：只保留 edge 鏡像盒式保護（兩腿共享同一組絕對價格邊界，任一邊界觸發即鎖定整對損益）。非對稱保護分支（獲利腿只留停損加移動停損、避險腿只留靜態停損不收斂）與單飛鎖定計算刪除。
- 獲利腿概念刪除：「一腿最大化獲利、另一腿只守每日最大虧損與單筆最大虧損」的不對稱目標（2026-09-08 Current Objective 所述）是本次需要移除的概念與設計，不是未來目標。兩腿永遠對稱，同受各自的日虧損預算與單筆上限約束；不存在 winner-only 分流、獲利腿移動停損續跑、避險腿靜態停損不收斂。
- 對側清空語意唯一化：`peer_leg_empty` 一律走跟隨關閉（存活腿立即開始關閉並收斂至 EMPTY），刪除「獲利腿單飛、虧損腿跟隨關閉」的 winner-only 分流。限時退出、操作員關機、休市、完整性路徑原本就走跟隨關閉，維持不變。
- 事件詞彙收斂：單飛事件（leader／follower 繼續單飛）與 solo 遙測不再產生；跟隨關閉事件保留為對側清空的唯一可觀測後果。重複 peer-empty 回報的去重邏輯保留，但去重對象只剩跟隨關閉。
- 角色權責不變：leader 仍是唯一的 canonical 政策作者、最佳進場候選評估者與立即派遣進場發起者；follower 仍是安全檢查執行者，不推導獨立 edge。配對設定檔權責規則中與趨勢相關的拒絕清單隨政策瘦身更新，follower 不得撰寫 shared 政策的不變量不變。
- 持久化相容策略：已持久化的 canonical 政策內容若含趨勢模式或趨勢鍵，視為需要操作員介入的不相容政策（fail-closed，不自動遷移為 edge）。量規劃、宇宙世代、配對路由、隔離狀態的持久格式不因本次簡化而改版。
- 報價管線瘦身：leader 本地分鐘級 mid buffer、去重 tape、逐門趨勢計數等只為趨勢服務的採集若無其他消費者則一併刪除；edge 所需的雙邊報價新鮮度、skew、point／tick value 快取保留。
- 測試接縫：沿用最高的現有接縫——配對執行單元介面（政策驗證 → 候選評估 → 立即派遣進場 → peer-empty 處置 → desired-EMPTY 收斂）。不為刪除工作新增接縫；趨勢偏置純函數的單元接縫隨函數刪除而消失。

## Testing Decisions

- 好的測試只驗證外部行為（能否進場、保護形狀是否為鏡像盒、對側清空是否跟隨關閉、政策雜湊是否收斂），不驗證已刪除的內部實現（偏置分數、趨勢 buffer 內容）。
- 受測模組：配對執行單元的政策驗證、最佳進場候選評估、立即派遣進場的 follower 安全檢查、peer-empty 跟隨關閉與收斂、啟動設定檔權責拒絕。
- Prior art：沿用現有的 edge 鏡像保護測試、peer-empty 跟隨關閉測試、政策雜湊逐字驗證測試、設定檔越權拒絕測試的風格；趨勢偏置、動量進場、雙向單飛續跑、單飛鎖定、重複 peer-empty 單飛去重的既有測試隨產品碼刪除。
- 驗收重點：全量測試套件綠燈；貪婪搜尋殘留的趨勢／單飛／獲利腿詞彙零命中（產品碼與測試，含 `entry_mode`、`trend_*`、`donchian`、`momentum`、`solo`、`profit leg`）；舊趨勢政策與含 `entry_mode` 鍵的政策載入時 fail-closed 的單測。

## Out of Scope

- 主控台 relay、控制平面帳本、配對保留／接受載荷、初始相容商品探索與宇宙世代、逐商品量規劃演算法、配對商品隔離、重連後冷靜參數值的調整。
- 部署模式開關（shadow／live）與 `allow_live` 語意：與進場策略無關，維持不變。本 spec 刪除的是策略選擇鍵（entry_mode），不是部署模式鍵（mode）。
- 單腿允許損失公式、日虧損預算曆日語意、`maximum_loss_per_trade_usd` 數值的任何放寬或收緊。
- 歷史日誌重播工具對舊趨勢 tape 的讀取相容（舊 tape 只讀即可，不保證新碼能回放）。
