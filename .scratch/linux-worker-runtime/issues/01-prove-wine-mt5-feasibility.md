# 01 - Prove Wine and MT5 feasibility

Category: enhancement
Status: ready-for-human

## Agent Brief

**Category:** enhancement
**Summary:** Prove the pinned Ubuntu/Wine/MetaTrader5 runtime and demo-order lifecycle before Linux Worker implementation begins.

**Why this requires a human:**
The proof requires access to a dedicated disposable MT5 demo account, an
installed broker terminal, a real broker connection, and explicit authorization
to create and close a live demo-market position. Those credentials and external
side effects must not be delegated to an unattended agent.

**Current behavior:**
`abt-worker` rejects every non-Windows platform. Its native adapter imports the
Windows-only MetaTrader5 Python package in-process, and there is no tested Wine
runtime or native-Linux-to-Wine process boundary.

**Desired behavior:**
A throwaway prototype on Ubuntu 24.04 LTS x86_64 should prove that a native
Linux parent can own a Windows Python bridge under 64-bit Wine, exchange every
required class of MT5 request through bounded inherited pipes, survive defined
bridge failures safely, and complete a minimum-volume market open/close
roundtrip on a clean disposable demo account. The result is a documented go/no-go
decision, not production code.

**Key interfaces:**
- Native parent/Wine bridge boundary - inherited stdin/stdout pipes carrying a versioned, length-prefixed request/response protocol; stderr carries diagnostics only.
- MT5 capability surface - initialization, login, account and terminal evidence, symbols, ticks, rates, orders, positions, calculations, order checks, and market order send/close behavior needed by the current Worker.
- Failure contract - timeout, malformed frame, bridge crash, Wine exit, and MT5 failure produce explicit outcomes; a post-send disconnect is treated as an unknown outcome and is never blindly retried.
- Compatibility matrix - exact Ubuntu, Wine, Windows Python, MetaTrader5 wheel, broker terminal build, and architecture versions used by the proof.

**Acceptance criteria:**
- [ ] The test host is Ubuntu 24.04 LTS x86_64 with a recorded, reproducible Wine/Windows Python/MetaTrader5/terminal version matrix.
- [ ] A native Linux parent starts and owns the Wine bridge without a shell, socket listener, password argument, password environment variable, or persisted IPC file.
- [ ] Split frames, oversized frames, unknown protocol versions, mismatched response IDs, bridge stderr output, timeout, and bridge exit are exercised and produce explicit safe failures.
- [ ] The bridge initializes MT5, logs in, and returns actual account, terminal, symbol, tick, rates, orders, and positions data through the inherited-pipe protocol.
- [ ] Margin/profit calculations and `order_check` complete through the same bridge.
- [ ] The operator confirms the account is a dedicated disposable demo account with no starting orders or positions; the prototype refuses to continue otherwise.
- [ ] With a separate explicit confirmation immediately before the side effect, the prototype opens a broker-minimum-volume market position, records its ticket and result, closes it, and verifies zero remaining orders and positions.
- [ ] A failed or uncertain close stops the prototype, reports the affected ticket prominently, and requires manual cleanup; it is never reported as success.
- [ ] MT5 passwords and returned credentials are absent from argv, environment variables, files, logs, tracebacks, diagnostics, and retained protocol captures.
- [ ] The prototype records startup, graceful shutdown, timeout, crash, restart, and post-send unknown-outcome observations.
- [ ] Findings document exact reproduction steps, observed limitations, the pinned support matrix, and a clear go/no-go recommendation for the production Linux Worker.

**Out of scope:**
- Production-quality bridge, TPM keystore, packaging, or Linux Worker implementation.
- Real-money accounts or non-demo broker operations.
- Automated cleanup after an uncertain broker outcome.
- Linux distributions other than Ubuntu 24.04 LTS x86_64.
- Remote MT5 terminals, TCP listeners, AF_UNIX under Wine, systemd deployment, containers, or Linux Trader support.
