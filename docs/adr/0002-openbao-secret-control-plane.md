# Use OpenBao for the secret control plane

The controller uses self-hosted OpenBao with integrated Raft storage for signing keys, device-certificate PKI, secret access policy, and auditability. OpenBao was chosen over HashiCorp Vault Community because its MPL-2.0 license avoids BUSL-1.1 licensing risk while retaining the required Vault-compatible API and single-service deployment; Infisical was rejected because PostgreSQL and Redis add unnecessary operational dependencies at this scale. OpenBao uses same-host SoftHSM and a version-locked PKCS#11 KMS plugin for auto-unseal, with a startup health check that verifies it can read a least-privilege test secret; this restores availability after a controller restart while accepting that a full controller-host compromise encompasses both sealed data and the unseal mechanism. The controller control plane is deployed with Docker Compose.
